# PSWGCommon: catálogo lexical das fontes

Gerado por `scripts/inventory_pswgcommon.py`, usando apenas a biblioteca padrão do Python. O [inventário JSON](../../data/pswgcommon-inventory.json) contém todos os arquivos sob `src`, SHA-256, tamanho, pacote, tipos reconhecidos, referências de CRC e vínculos nominais.

Revisão de referência: `9ab4234e94be480f3b48f539a1f0dd6f5bd408a4`. Arquivos: **433**; Java/Kotlin: **431**; arquivos sob `src/test`: **5**; candidatos em `network/packets`: **238**.

## Escopo e limites

A cobertura é lexical: expressões regulares com comentários e strings mascarados, sem AST, resolução de herança, call graph, execução, decompilação ou comparação de payloads. A lista de candidatos inclui classes auxiliares no diretório de packets. Os tipos de topo são reconhecidos apenas quando a declaração tem forma simples; funções Kotlin, aliases e estruturas complexas podem não receber um tipo identificado. Valores de CRC são literais extraídos, não calculados. Arquivos não Java/Kotlin recebem hash, mas não análise de declarações.

A associação com `content/protocols` compara o nome da classe/arquivo e os argumentos literais de `getCrc` com o título ou nome do arquivo Markdown, ignorando caixa e pontuação. Ela não verifica opcode, direção, versão, campos ou compatibilidade. Todas as correspondências são candidatas; múltiplas páginas ou arquivos com o mesmo nome são mantidos e expostos como ambiguidades no JSON, sem escolher uma silenciosamente.

Os links GitHub fixam a revisão Git. Os hashes descrevem os bytes locais; alterações locais ou arquivos não rastreados podem divergir dessa revisão. O JSON registra o estado Git de `src`.

Para regenerar, execute `python scripts/inventory_pswgcommon.py` na raiz de `swgdocs`. Use `--source` e `--docs` para outras localizações. Não há timestamps na saída.

Grupos de nomes de fontes duplicados: **0**; nomes associados a múltiplas páginas: **2**; arquivos com múltiplos tipos de topo reconhecidos: **0**; tipos de topo com nome qualificado repetido: **0**.
